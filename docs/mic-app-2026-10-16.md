# mic_app desktop milestone, 2026-10-16

The Windows application uses Tauri 2, Vue 3 and TypeScript, with a Rust serial
worker. The standalone executable is `mic_app/release/mic_app.exe`; source,
commands and usage are in [the app README](../mic_app/README.md).

## Delivered functionality

- Exposed-port azimuth compass, accepted/rejected/stale/off/disconnected states,
  expected-source marker and 20-second history.
- Raw channel RMS/dBFS, all six pair delays/coherence, fit residual, direction
  update rate, newest-sample age and capture/analysis health counters.
- Port selection, estimation controls, optional reconnect, simulated data.
- Expected-angle trials with placement annotations, acceptance rate, circular
  mean and bias, absolute errors and circular deviation.
- JSON/CSV export, JSON import, recorded-session replay with play/pause/scrubbing.

No elevation, front/back, range, calibrated accuracy or automatic steering is
implied. Simulation is labeled and never opens the board. Trials are held in
memory until exported. Disconnection finishes an active trial. The app keeps
UAC2 audio independent of CDC telemetry.

## Firmware changes

`doa telemetry` returns one v1 JSON snapshot. The four RMS values use the same
8192 raw frames as the estimator; angle/delay calculations are unchanged.
The backend requests no faster than 170 ms, with one telemetry request in flight.
It disables terminal echo while connected and restores echo on exit. This avoids
unnecessary small transfers and request buildup during UAC operation.

The shell print buffer is 512 bytes. Only the bounded telemetry JSON write
temporarily uses priority 1, restored immediately afterward; DMA and USB still
outrank it. No extra firmware streaming thread or PCM buffer is allocated.
The app detects absent/unsupported telemetry after four seconds and releases
the port on disconnect. An obsolete-epoch result is explicitly marked unusable.

## Evidence and limits

- 61 existing Python/native firmware tests pass after adding the RMS values.
- Five TypeScript tests cover circular statistics, rejection/stale/off gates,
  session validation/round trip and CSV quoting.
- Three browser UI tests cover simulation, trial/export/import/replay,
  disconnected state, malformed sessions, rejection and recovery.
- Rust transport framing/version tests pass; the ignored live-device test
  exercises the production serial worker, not a second host implementation.
- `build-tests/mic-app/native-smoke.json` and `native-device.png`: standalone
  Tauri/WebView2 connected to COM14, received telemetry, disabled/re-enabled
  estimation, recorded a trial and disconnected with no JavaScript errors.
- Final combined-load evidence: `live-transport.json`,
  `final-echo-pattern.wav` and its transport/pattern reports. Intermediate files
  retain unsuccessful delivery-rate trials; those are not final passing tests.

Native testing used ambient room sound, so near-normal/poor-band rejections are
expected. UI and numerical checks do not validate acoustic angular accuracy.
Controlled known-position trials remain the next physical validation task.

Final measurements: 292 telemetry responses in 60 seconds (4.87 Hz; median
host response interval 206 ms, maximum 248 ms). The estimator itself completed
results every 171 ms median, 179 ms maximum among telemetry samples. Median
newest-sample-to-publication delay was 45.690 ms, maximum sampled 52.956 ms.
These are observations, not hard deadlines. Host polling can skip intermediate
board results; trial statistics describe the received results.

The final 60-second UAC pattern contains 672 startup zero frames followed by
2,879,328 consecutive frames, with zero sequence/channel errors. Windows reports
no flags/position gaps. Capture drops/faults and analysis overwrites stayed zero;
reset count stayed at two throughout the serial test (earlier configuration
changes). Device USB underruns/overruns/gaps/send/pool errors remain zero;
transient active-busy returns occurred without loss of queued frames.

`final-frame.doa.json` passes the same-frame host comparison, maximum pair
difference 0.001485 sample. `levels-check.json` compares the new channel RMS
telemetry with that exact raw frame: maximum error 0.000469 PCM count.
The board is left with broadside, learned full-band suppression and DOA enabled,
pattern off, shell echo on and COM14 free. Reboot defaults remain raw/DOA off.
